# 实测记录：中兴 F7610U 开启 Telnet

> 环境：Debian 13.7 (trixie) / x86_64 / 内核 6.12
> 日期：2026-10-31
> 设备：中兴 F7610U，固件 V1.2.0P1N28，联通定制

## 起因

手上有一个 Windows 版「书院烧香中兴telnet开启工具（第二款）」，每次要开 telnet 都得切到 Windows。想直接在 Debian 宿主机上搞定。

## 分析过程

### 1. 拆包定位真实逻辑

工具目录里有两个文件：

- `书院烧香中兴telnet开启工具.exe` — 15MB，PE32 GUI 程序
- `telnet.exe` — 7.9MB，PE32+ 控制台程序

主程序是加壳的 .NET，静态字符串里只有版本资源，看不到任何业务逻辑：

```
$ strings -el 书院烧香中兴telnet开启工具.exe
DEFAULT_ICON / VS_VERSION_INFO / FileVersion / ProductName ...
```

但 `telnet.exe` 是 Go 编译的原生程序，符号表还留着，直接暴露了真实来源：

```
$ strings -n 8 telnet.exe | grep -oE 'github\.com/thank243/[a-zA-Z0-9_/\.\-]+' | sort -u

github.com/thank243/zteOnu/app/factory.getKeyPool
github.com/thank243/zteOnu/app/factory.New
github.com/thank243/zteOnu/app/telnet.New
github.com/thank243/zteOnu/cmd.run
github.com/thank243/zteOnu/utils.ECBEncrypt
```

关键字符串：

```
webFac
SendSq.gch?rand=%d
CheckLoginAuth.gch?&version61&user=%s&pass=%s
FactoryMode.gch?mode=2&user=notused
permanent telnet (user: root, pass: Zte521)
MAC address is not set to 00:07:29:55:35:57
```

结论：这个 exe 的干活部分就是 **zteOnu**，只是套了个 GUI 壳，还额外加了 TSLan 相关字段。

### 2. 判断可行性

zteOnu 的工作方式是：

1. HTTP POST 到光猫的 `webFac` 接口，走一串 `SendSq.gch` / `CheckLoginAuth.gch` / `FactoryMode.gch`
2. 拿到临时 telnet 凭据
3. 用 telnet 登录，写入永久配置

**全程只有 HTTP 和 telnet 网络交互，不碰任何 Windows API。** 所以完全可以原生编译，不需要 wine。

### 3. 找源码

原作者 `thank243/zteOnu` 仓库**已被删除**，现在该仓库名被一个无关项目占用（`description` 是另一个项目的内容）。没有 release 可下。

可用的是 fork：**[Septrum101/zteOnu](https://github.com/Septrum101/zteOnu)**，源码完整，最后提交 2026-08-19。

代码结构干净：

```
app/crypto/   AES ECB 加解密
app/factory/  webFac 认证流程
app/onu/      临时/永久 telnet 编排
app/telnet/   telnet 客户端
cmd/          CLI 入口
```

## 编译

Debian 上原本没有 Go，装 Go 1.27.3：

```bash
curl -sL -o go.tgz https://go.dev/dl/go1.27.3.linux-amd64.tar.gz
sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf go.tgz
export PATH=/usr/local/go/bin:$PATH
```

编译：

```bash
git clone --depth 1 https://github.com/Septrum101/zteOnu.git
cd zteOnu
go build -trimpath -ldflags '-s -w' -o zteonu .
```

产物 7.6MB，ELF x86-64，一次通过，无报错。

## 第一次尝试：失败

```bash
$ ./zteonu -i 192.168.1.1 --port 80
step [0] reset factory: ok
step [1] request factory mode: ok
step [2] send sq: ok
step [3] check login auth: [00:e0:4c:68:0a:76] factory flow failed: errors user or password
```

前 3 步畅通，卡在认证。

### 误判一：以为是 MAC 问题

使用说明里写着「新版固件请先修改网卡 MAC 为 `00:07:29:55:35:57`」。试一下：

```bash
$ ./zteonu -i 192.168.1.1 --port 80 -m 00:07:29:55:35:57
step [3] check login auth: [00:07:29:55:35:57] factory flow failed: errors user or password
```

**换 MAC 没用，照样 401。** 说明问题不在 MAC。

查看源码 `app/factory/flow.go` 确认错误来源：

```go
case 401:
    return errors.New("errors user or password")
```

设备端明确返回 `CheckLoginAuth.gch` 认证失败——是**凭据不对**，不是 MAC 不对。

### 逐组探测凭据

```bash
for combo in 'telecomadmin:nE7jA%5m' 'telecomadmin:admin' 'admin:admin' \
             'telecomadmin:telecomadmin' 'root:Zte521' 'admin:Zte521' \
             'CUAdmin:CUAdmin' 'telecomadmin:nE7jA%5m.' 'user:user'; do
    ...
done
```

结果：

```
[telecomadmin / nE7jA%5m]        => errors user or password
[telecomadmin / admin]           => errors user or password
[admin / admin]                  => errors user or password
[telecomadmin / telecomadmin]    => errors user or password
[root / Zte521]                  => errors user or password
[admin / Zte521]                 => errors user or password
[CUAdmin / CUAdmin]              => telnet verified, temp factory telnet is open   ✓
[telecomadmin / nE7jA%5m.]       => errors user or password
[user / user]                    => errors user or password
```

**命中：`CUAdmin / CUAdmin`** —— 联通定制固件的默认超管账号。

## 固化永久 telnet

## 结论

| 项目 | 结果 |
|---|---|
| Linux 原生运行 | ✅ 无需 wine |
| 编译 | ✅ Go 1.27.3，一次通过 |
| 临时 telnet | ✅ 认证通过 |
| 永久 telnet | ✅ 固化成功，未重启设备 |
| 实际登录 | ✅ root / Zte521 |

两个关键结论：

1. **8080 关闭是常态**，先探测端口，别死磕默认值
2. **凭据比 MAC 重要**，401 就换凭据，别在 MAC 上浪费时间
